# Milcar

The website and dealership platform of Milcar, automotive consultancy (Lebanon): a public showroom in
English, French and Arabic, and a staff dashboard for the inventory, customers, leads and private viewings.

This branch (`platform`) is being built in ten phases; [DEVELOPMENT_PROGRESS.md](DEVELOPMENT_PROGRESS.md)
says where it stands. Until the switch, the live website is the current site on `main`, published by GitHub
Pages and described in [SETUP.md](SETUP.md); its admin page still edits the cars, and every change there is
mirrored into the platform's tables (docs/DATABASE.md, part 11).

## Stack

| | |
|---|---|
| App | Next.js 16 (App Router), React 19, TypeScript 7 |
| Look | `src/styles/site.css`, the site's own stylesheet, plus Tailwind CSS 4 for new screens, built on the same design values (`src/app/globals.css`) |
| Languages | next-intl on the server: English at `/`, French at `/fr`, Arabic at `/ar` (right to left; both open in Phase 8). Words in `messages/*.json` |
| Data, logins, files | Supabase: Postgres with row level security, Auth, Storage |
| Hosting | Vercel (planned) |

## Run it on your computer

Needs Node.js 24.

```bash
npm install
cp .env.example .env.local   # then fill in the values (see the comments in the file)
npm run dev                  # http://localhost:3000
```

| Command | What it does |
|---|---|
| `npm run dev` | The platform, reloading as you edit |
| `npm run build` | Lists the pictures, builds the walk-in engine, type-checks, then builds the site for production |
| `npm start` | Serve that build |
| `npm run test:db` | Every database rule, on an in-memory Postgres (no Supabase project needed) |
| `npm run typecheck` | TypeScript only |
| `npm run assets` | Rewrite the list of pictures and the walk-in engine (the two commands above do it for you) |

## Where things are

| Path | What |
|---|---|
| `src/app/[locale]/` | The public pages: `page.tsx` (home), `inventory`, `car/[slug]`, `featured`, `brands`, `brands/[slug]`, `about`, `contact`, `private-viewing`, plus the not-found and error pages |
| `src/components/` | The site's sections (walk-in, featured windows, promise, hold-to-build, teaser, steps, questions, booking form, footer), the nav, the car card and the inventory filters |
| `src/lib/home.ts`, `src/lib/build.ts` | The walk-in and hold-to-build engines. `home.ts` is also built into `public/engine/home.js` (`scripts/build-engine.mjs`) so the walk-in starts before the rest of the code arrives |
| `src/lib/catalog.ts` | What the public pages read: published cars, brands, the business details and opening hours |
| `src/lib/media.ts`, `src/data/asset-manifest.ts` | Pictures by their plain path (`assets/cars/f8.webp`) and uploads by their bucket; the manifest is generated by `scripts/assets-manifest.mjs` |
| `src/lib/labels.ts`, `src/lib/seo.ts` | Body-type names, prices, opening hours, WhatsApp links; each page's title, description and sharing picture |
| `src/i18n/` | The languages: routing, loading the words, and `link.tsx`, the language-aware link the pages use |
| `src/lib/supabase/` | The ways to reach Supabase: `public` (visitors' view, cacheable), `server` and `browser` (as the logged-in member of staff, so their rules apply), `admin` (the server's own key, server only) |
| `src/lib/env.ts`, `env.server.ts` | Settings, checked when first used. Secrets are in `env.server.ts`, which browser code cannot import |
| `src/proxy.ts` | Runs before each page: the current site's old addresses (`car.html?id=…`), the dashboard's login check, the language |
| `src/assets/` | The pictures and fonts. Videos are in `public/assets/` |
| `supabase/migrations/` | The database, in eleven files, applied to the live project. See [docs/DATABASE.md](docs/DATABASE.md) |
| `src/types/database.ts` | TypeScript types for every table, generated from the live database (regenerate after each migration) |
| `supabase/tests/` | The database tests |
| `supabase/setup.sql` | The current site's database (kept as it is) |
| `messages/` | The words of the site in each language |

## Security

- The browser only ever gets the Supabase **publishable** key. The **secret** key lives in the server's
  environment only (`SUPABASE_SECRET_KEY`); `src/lib/env.server.ts` cannot be imported by browser code.
- Every table has row level security. Visitors read published cars, brands, opening hours and public settings,
  nothing else. Website forms go through the server (spam check, rate limit), never straight to the database.
- Roles (owner, manager, salesperson, inventory editor) are enforced by the database itself; see
  [docs/DATABASE.md](docs/DATABASE.md).
- `.env.local` and every `.env.*` except `.env.example` are never uploaded.
