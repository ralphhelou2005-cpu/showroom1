# Milcar

The website and dealership platform of Milcar, automotive consultancy (Lebanon): a public showroom in
English, French and Arabic, and a staff dashboard for the inventory, customers, leads and private viewings.

This branch (`platform`) was built in ten phases; [DEVELOPMENT_PROGRESS.md](DEVELOPMENT_PROGRESS.md) says where
it stands. Until the switch, the live website is the current site on `main`, published by GitHub Pages and
described in [SETUP.md](SETUP.md); its admin page still edits the cars, and every change there is mirrored into the
platform's tables (docs/DATABASE.md, part 11). [Going live](#going-live) lists what the switch needs.

## Stack

| | |
|---|---|
| App | Next.js 16 (App Router), React 19, TypeScript 7 |
| Look | `src/styles/site.css`, the site's own stylesheet, plus Tailwind CSS 4 for new screens, built on the same design values (`src/app/globals.css`); `src/styles/rtl.css` mirrors it for Arabic |
| Languages | English at `/`, French at `/fr`, Arabic at `/ar` (right to left). Words in `src/i18n/words.ts`; next-intl reads the language from the address, on the server only |
| Data, logins, files | Supabase: Postgres with row level security, Auth, Storage |
| Email | Resend (optional: until it is connected, every email is recorded as not sent) |
| Hosting | Vercel (planned) |

## Run it on your computer

Needs Node.js 24.

```bash
npm install
cp .env.example .env.local   # then fill in the values (see the comments in the file)
npm run dev                  # http://localhost:3000
```

| Command | What it does |
|---|---|
| `npm run dev` | The platform, reloading as you edit |
| `npm run build` | Lists the pictures, builds the walk-in engine, type-checks, then builds the site for production |
| `npm start` | Serve that build |
| `npm run test:db` | Every database rule, on an in-memory Postgres (no Supabase project needed) |
| `npm run test:e2e` | The dashboard, the CRM and the website's booking form end to end in a real browser, against a local stand-in for Supabase (see Testing) |
| `npm run typecheck` | TypeScript only (`tsconfig.check.json`: the project without the files `next dev` generates) |
| `npm run assets` | Rewrite the list of pictures and the walk-in engine (the two commands above do it for you) |

## The dashboard

`/admin`, for the showroom's team. Everyone signs in with an email and a password; there is no public sign-up.

- **Overview:** cars on sale (reserved, drafts, sold); open leads (new, unassigned, follow-ups due, sales in the last
  30 days; a salesperson sees their own); viewings in the next 7 days and today, with requests to approve; the team.
  Each figure links to its page.
- **Leads:** every inquiry, newest first, filtered by status, source, the person it is assigned to, follow-ups due,
  or a search; a CSV of what is shown. A lead holds the customer (with call and WhatsApp buttons), the car, the
  status from new to won or lost, who has it, the next follow-up, notes, a history of calls and messages (logging a
  call moves a new lead to "Contacted"), and its viewings. Staff add leads from a call or a visit too.
- **Viewings:** a diary: requests to approve first, then each day ahead, then the last month. Managers and the owner
  confirm; anyone on the sales team moves a viewing, marks it done or "didn't come", or cancels it with a reason.
  Confirming, moving or cancelling emails the customer once email is connected.
- **Customers:** everyone who asked, with their leads and viewings, their details and a CSV. A salesperson sees
  their own leads and the unassigned ones (and picks one up by taking it), and the customers behind them.
- **Inventory:** every car, in the website's order, with search and filters. Its editor holds the details, the text in
  English, French and Arabic (Arabic right to left), the specs, whether it shows on the website, its status
  (reserving and selling are for managers and the owner), whether it is one of the home page's featured cars, and its
  photos and videos. Photos are resized in the browser before they upload; videos up to 50 MB play in the car's
  gallery. A car can be duplicated as a draft, archived, or deleted by a manager or the owner. Every change shows on
  the website at once.
- **Brands:** names, the words on each brand's page, whether it shows, and the order.
- **Analytics** (managers and the owner): visitors, pages and cars seen, taps on WhatsApp and phone, new leads, each
  day of the last 7, 30 or 90 days, the most seen cars, where visitors and leads came from.
- **Settings** (managers and the owner): the showroom's details (they appear in the footer and on the contact page as
  soon as they are saved, and nothing shows while they are empty), opening hours, closed days, the booking rules
  (viewing length, how far ahead, notice, whether requests need approval), who receives the new-inquiry emails, and,
  for the owner, what is connected.
- **Team** (the owner): invitations, roles, switching people off and on, new sign-in links.
  - **Invitations:** the server creates the login and gives the owner a one-time link to send by WhatsApp (or copy
    into an email). The person chooses their password on a page whose **Continue** button alone uses the link,
    because WhatsApp and email scanners open links to preview them.
  - A switched-off person can no longer see or change anything, and can't sign in again until switched back on.
    There is always an owner.
- **Forgotten passwords:** **Forgot your password?** sends an email through Supabase; the owner can also make a
  new sign-in link for anyone from **Team**, which needs no email.
- Each role sees only the pages it uses.

### Supabase settings the dashboard needs (once, in the Supabase dashboard)

1. **Authentication → URL Configuration:** Site URL = the site's address; add `<site>/admin/auth/confirm` to
   the Redirect URLs (and `http://localhost:3000/admin/auth/confirm` for your computer).
2. **Authentication → Sign In / Providers → Email:** switch off **Allow new users to sign up** (invitations
   don't need it).
3. **Authentication → Emails → Reset password:** so the link also works when opened on another device, make the
   link `{{ .SiteURL }}/admin/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`.
4. Supabase's built-in email only reaches the project's own team members, a few times an hour. Until Supabase is set
   to send through Resend (Authentication → Emails → SMTP), staff who forget their password get a new link from the
   owner.
5. The server needs `SUPABASE_SECRET_KEY` for invitations, new sign-in links, the website's booking form, visit
   counts and the rate limits. Without it, each of those says it is off; everything else works.

## The website's booking form

"Book a private viewing" (home page, contact and private-viewing pages, and every car page's button, which fills in
the car) asks for a name, a phone number in international form, the car, and, once opening hours are set, a time
from the free ones (`available_slots`, within the hours and the booking rules, minus closed days and viewings already
booked). `src/app/[locale]/booking-action.ts` checks it on the server (a hidden trap field, 6 requests an hour from one
address and 4 a day from one phone, Cloudflare Turnstile once it is connected), then the database saves the customer
(found again by phone or email), the lead and the requested viewing in one step (`submit_inquiry`), and the team is
emailed. The visitor is told plainly what happens next: a time noted and to be confirmed, or a call back. If the
form can't reach the database it says so and offers WhatsApp; it never pretends a request was sent.

## Languages

English has the plain addresses; French and Arabic add `/fr` and `/ar`. Every page says which other languages exist
(for search engines) and the footer switches language on the same page. Arabic is right to left, with its own fonts
(Amiri for titles, IBM Plex Sans Arabic for text, downloaded only for Arabic letters); the walk-in and the featured
windows keep their direction, and English car names, specs and phone numbers read left to right inside Arabic text. A car's text comes from the car editor in each
language, and shows the English where a translation is missing; the usual spec names (Engine, Power…) are translated
by themselves. The French and Arabic words of the site should be read by a native speaker before launch.

## Analytics

`src/components/Analytics.tsx` tells the server which page was seen, which car, and taps on WhatsApp and phone
links. No cookies and nothing stored in the browser: a visitor is counted with a hash of the day, their address and
browser, and a secret (`ANALYTICS_SALT`), which can't be traced back and changes every day. Visitors who ask not to
be tracked (Do Not Track, Global Privacy Control) and robots aren't counted. Without `ANALYTICS_SALT` and the secret
key, nothing is recorded and the Analytics page says so; leads are counted either way.

## Search engines

Each page has its title, description, sharing picture and language alternates; `/sitemap.xml` lists every page and
car in the three languages, `/robots.txt` keeps the dashboard out, the home page describes the business
(opening hours, address, phone, once they are in Settings) and each car page describes the car, for search results.

## Backups

Supabase's free plan keeps no backups you can download. `.github/workflows/backup.yml` makes one every night at
01:30 UTC: a copy of the database encrypted with a passphrase before it leaves GitHub's machine, kept 30 days.
It runs from the default branch once two repository secrets exist (Settings → Secrets and variables → Actions):
`SUPABASE_DB_URL` (Supabase → Connect → Session pooler, with the database password) and `BACKUP_PASSPHRASE` (a long
random passphrase kept somewhere safe outside GitHub). Without them it says so and stops. To restore:
`gpg -d milcar-<date>.sql.gpg > dump.sql`, then `psql "$URL" < dump.sql`. Supabase Pro adds daily backups of its own.

## Testing

- `npm run test:db`: every migration and access rule, on an in-memory Postgres set up like a Supabase project.
- `npm run test:e2e`: the platform in a real browser (Chrome) at computer and phone sizes: logins and the team
  (`e2e/dashboard.e2e.ts`), the inventory from a new draft to the public pages (`e2e/inventory.e2e.ts`), and the
  booking form, settings, viewings, leads, customers, CSV files, a salesperson's limits, analytics, the French and
  Arabic pages and the sitemap (`e2e/crm.e2e.ts`). It runs against `e2e/fake-supabase.ts`, a stand-in for Supabase
  Auth, its data API and storage built on the same in-memory database, so no test ever signs in to or writes to the
  live project. Start the platform pointed at the stand-in first:

```bash
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_e2e_local_only SUPABASE_SECRET_KEY=sb_secret_e2e_local_only NEXT_PUBLIC_SITE_URL=http://localhost:3300 ANALYTICS_SALT=e2e-local-only-salt-0123456789abcdef0123 npx next dev -p 3300
```

```bash
npm run test:e2e
```

## Security

- The browser only ever gets the Supabase **publishable** key. The **secret** key lives in the server's
  environment only (`SUPABASE_SECRET_KEY`); `src/lib/env.server.ts` cannot be imported by browser code.
- Every table has row level security. Visitors read published cars, brands, opening hours and public settings,
  nothing else. The booking form goes through the server (trap field, rate limits, spam check), never straight to
  the database; `submit_inquiry` can only be called with the secret key.
- Roles (owner, manager, salesperson, inventory editor) are enforced by the database itself; see
  [docs/DATABASE.md](docs/DATABASE.md). Every dashboard page and action checks the role on the server too.
- The secret key creates an invited person's login (and removes it again if the invitation can't be completed),
  makes one-time sign-in links, blocks a switched-off person's login, saves the booking form's requests, records
  visits and counts attempts for the rate limits. Everything else runs as the signed-in person, so the database's
  rules and its audit log apply.
- Sign-ins, password emails, invitations, password changes and booking requests are rate limited, and no answer
  reveals whether an email has a login.
- In production every page carries a content security policy (scripts, styles and fonts only from the site itself;
  pictures and videos also from the project's storage; Cloudflare's spam check only once it is connected), and
  headers against framing, type sniffing and leaking addresses.
- `.env.local` and every `.env.*` except `.env.example` are never uploaded.

## Going live

The platform replaces the current site in one switch, once the owner has decided on hosting and the domain. In order:

1. **Hosting** (Vercel Pro, about $20 a month, since the free plan forbids commercial use, or another Next.js host):
   import the repository's `platform` branch, Node.js 24.
2. **Server settings** on the host (see `.env.example`): `NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_SITE_URL` (the final address), `SUPABASE_SECRET_KEY`,
   `ANALYTICS_SALT` (32+ random characters). Optional: `RESEND_API_KEY` and `EMAIL_FROM` (an address on a domain
   verified in Resend), `NEXT_PUBLIC_TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY`.
3. **Database part 14** (`submit_inquiry`, `analytics_summary`) applied to the live project, then the types
   regenerated. Parts 1 to 13 are applied already.
4. **Supabase settings** for the dashboard (above), with the final address.
5. **Try it** on the host's preview address: sign in, invite a colleague, add a car, book a viewing from a phone,
   confirm it; check Settings → Connections.
6. **The owner's details** in Settings: address, map link, hours, phone, WhatsApp, email, booking rules; the team's
   invitations; decide whether the six sample cars stay (each is one click to "Draft").
7. **The switch:** point the domain at the host; then switch off the mirror (part 11, docs/DATABASE.md) and retire
   the current admin page, since the new dashboard edits the cars from then on; switch off GitHub Pages' deploy on
   `main`.
8. **Backups:** the two repository secrets (see Backups), then run the workflow once by hand.
9. **After launch:** PageSpeed Insights on the real address, Google Search Console with the sitemap, a native speaker
   reading the French and Arabic.
